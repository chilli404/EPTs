One Model, Many DAGs

A complete guide to the execution-graph equivalent Transformers experiments

1. The Problem: Execution-Graph Specialization

A standard Transformer block runs Attention first, then FFN (sequential execution). An alternative is to run them in parallel from the same input — this enables matmul fusion and communication overlap in multi-GPU setups.

The problem: a model trained with one execution graph breaks catastrophically when switched to the other.

430M Specialist Collapse

A sequentially-trained 430M specialist, when forced to run in parallel:

54.2%
Top-token agreement (vs 96.5% polymorphic)
1,273
Symmetric KL (nats/token) — vs 4.68 polymorphic

BPB degradation: 0.279 (polymorphic: 0.002). The sequential specialist's output is effectively destroyed.

2. The Solution: Graph-Consistency Training

Run both execution graphs on every training batch. Optimize both language-model losses plus a consistency term that forces the two graphs to produce the same output distribution:

L = ½ Lseq + ½ Lpar + λ · ‖z̄seq − z̄par‖²

where z̄ are mean-centered logits. The result: one checkpoint that works under sequential, parallel, and arbitrary mixed-layer DAGs with negligible quality loss.

Key insight: The method is graph-consistency training, not a specific loss function. Both MSE and KL-based consistency objectives work — what matters is that you explicitly train for cross-graph agreement.

4. The Composition Law

Can we predict what happens with any mixed execution DAG — not just all-sequential or all-parallel?

Measure each layer's individual defect (the KL divergence when only that layer is switched to parallel). Then the composition model predicts the divergence of any combination:

D(m) ≈ α0 · Σ dl · |m|−β

where m is the set of parallel layers, dl are single-layer defects, and β > 0 captures subadditivity — multiple defects partially cancel rather than accumulate.

All results above use a nanochat-derived architecture (LayerNorm, ReLU², QK-norm, value embeddings, softcap). Does the phenomenon generalize? We tested a conventional Llama-style model (RMSNorm, SwiGLU, no value embeddings, no softcap).

Composition on Llama: 5-fold CV Pearson 0.827 (430M) → 0.846 (1B). Weaker than primary architecture (0.97) but the subadditive structure persists and improves with scale. The 2-parameter CA model beats linear on Llama too (Pearson 0.90 vs 0.83).

Graph specialization and consistency training are not artifacts of one architecture. Composition predictiveness is architecture-dependent, but calibration compensates (see Section 10).

The same checkpoint, compiled to different hardware, selects different optimal execution graphs:

The Apple Silicon result is particularly important: MPS prefers a genuinely different DAG than CUDA (layers 0, 3, 5, 7, 9 are faster sequential on M4). The compiler correctly selects this.

This is the core systems contribution: the execution graph becomes a post-training deployment variable. One training run, hardware-specific inference.

9. Pairwise Mechanism

Why does the composition law work? We evaluated all C(L,2) layer pairs to study how defects interact.

430M (190 pairs)7B (496 pairs)
Subadditive pairs100% (190/190)97% (481/496)
Mean cos(δi, δj)0.0110.042
cos ↔ interaction ρ-0.062 (ns)+0.260
distance ↔ cosine ρ-0.705-0.496

Findings:

  • Pairwise interactions are overwhelmingly subadditive — defects cancel when combined
  • Defect vectors are near-orthogonal (mean cosine ≈ 0.01–0.04)
  • Distant layers are more strongly opposed (distance↔cosine ρ = -0.71 at 430M)
  • But pairwise angular alignment alone does not predict interaction magnitude — the attenuation arises from network propagation, not simple vector cancellation

10. Compiler Calibration

The composition law is an empirical predictor, not a guarantee. Raw predictions violate the quality budget frequently. Calibration converts it into a conservative deployment rule:

ArchitectureRaw violations95% calibrated99% calibrated
Primary 430M36.1%1.9%0.6%
Llama 430M32.9%2.0%0.7%
Llama 1B47.1%2.6%0.5%
Even when the composition model is substantially less accurate (Llama, Pearson 0.83 vs 0.97), calibration turns it into a practical conservative compiler with <1% budget violations.
